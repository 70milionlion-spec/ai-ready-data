# ١. ما هذا؟

مشروع `analyzer` يقرأ ملفات CSV، يطبّع أسماء الأعمدة، يحذف الصفوف التي تحتوي قيماً مفقودة، ثم يكتب جدولاً منظماً إلى ملف CSV جديد. يناسب المطورين والمستخدمين الذين يريدون معالجة بيانات جداول بسيطة من خلال سطر الأوامر.

# ٢. كيف أشغله؟

يتطلب المشروع Python 3.11 أو أحدث. ثبّت الاعتماديات الموجودة في `requirements.txt`:

```text
python -m pip install -r requirements.txt
```

شغّل المعالجة باستخدام المسارات الافتراضية:

```text
python enrich.py
```

سيقرأ الأمر `data/raw/sales_sample.csv` ويكتب النتيجة إلى `output/enriched.csv`.

يمكن تحديد مسارات مختلفة باستخدام الوسائط:

```text
python enrich.py --input data/raw/sales_sample.csv --output output/enriched.csv
```

لتشغيل اختبارات المشروع:

```text
pytest tests/ -q
```

# ٣. كيف تعمل من الصفر؟

1. يستقبل `cli.py` وسائط `--input` و`--output`، أو يستخدم المسارات الافتراضية.
2. تستخدم `io.py` `pandas` لقراءة ملف CSV، وتنشئ ملف إدخال افتراضياً إذا لم يكن موجوداً، ثم تكتب جدول النتيجة.
3. تمرر `cli.py` الجدول إلى `logic.py`.
4. تنفذ `logic.py` قواعد العمل: تطبيع أسماء الأعمدة، والتحقق من عدم تكرارها، وحذف الصفوف ذات القيم المفقودة.
5. تعيد `cli.py` النتيجة إلى `io.py` لكتابتها في ملف الإخراج، ثم تطبع رسالة نجاح.

# ٤. البنية

```text
ai-ready-data/
├── data/raw/sales_sample.csv        # ملف CSV الخام الافتراضي
├── output/enriched.csv              # ملف CSV الناتج الافتراضي
├── src/analyzer/
│   ├── __init__.py                  # تعريف حزمة analyzer
│   ├── io.py                        # قراءة ملفات CSV وكتابتها وإنشاء ملف الإدخال عند الحاجة
│   ├── logic.py                     # الحسابات وقواعد العمل وتطبيع الأعمدة ومعالجة القيم المفقودة
│   └── cli.py                       # معالجة الوسائط واستدعاء الطبقات وطباعة الرسائل
├── tests/                           # اختبارات المشروع
├── enrich.py                        # نقطة تشغيل متوافقة مع الواجهة القديمة
├── requirements.txt                 # الاعتماديات المطلوبة
└── pyproject.toml                   # تعريف حزمة analyzer وإعدادها
```

## ٥. القرارات الهندسية والسبب وراءها (Design Decisions)

* **القرار الأول: هيكلة المشروع إلى ثلاث طبقات منفصلة (io, logic, cli)**
  * *السبب:* فصل منطق قراءة وكتابة البيانات (io) عن قواعد المعالجة والحسابات (logic) وعن واجهة أوامر المستخدم (cli). هذا الفصل يمنع تداخل المسؤوليات، يسهل صيانة الكود، ويسمح باختبار طبقة المنطق بالكامل بمعزل عن تفاصيل النظام والملفات.

* **القرار الثاني: اعتماد اختبارات وحدة صارمة وفحص الحساسية (Mutation & Unit Testing)**
  * *السبب:* ضمان التطابق التام والمطلق للمخرجات بنسبة 100% مع الملف المرجعي (baseline.csv) دون أي انحراف (Byte-to-Byte Matching)، والتأكد من أن الاختبارات حساسة وحقيقية وتكتشف أي خطأ طارئ أو متعمد في الكود لرفع موثوقية النظام.
